# Protected-route and public website changes

The supplied repository and the later live residence snapshot agree on the four engine URLs. The matching eKaya admin HTML was recovered from `rezflow-residences-2027.zip`; its existing live config remained in place. The two forms and their student scripts include the later `rezflow-multiple-submissions-patch.zip`. The site keeps the original homepage imagery, type, navigation, mail enquiry and plan content. Demo cards open isolated residence/role links. The previous homepage advertised the operational Phumelela admin as a demonstration, pointed at some missing routes and linked to recordings with potentially identifiable records. The three video paths now contain 24-second synthetic walkthroughs recorded from the actual rebuilt screens. Student and management video players have fresh posters and English caption tracks. Supplied original media remains in the owner's source backup. A public-facing contact link prepares an email for the visitor to review and send.

The protected Chromium suite ran with isolated sample data and intercepted webhook replies. It covers both capture directions, multiple students per browser, unique new IDs, a retained ID on retry, wrong receipts, rejected requests and staff-key denial. For both reporting pages it verifies local/all-residence, status and search filters, totals, pagination and detail views. Browser dimensions of 360, 768 and 1440 CSS pixels fit without horizontal overflow. Actual residence GET/POST availability and the currently published n8n version need an authorised staging check.
